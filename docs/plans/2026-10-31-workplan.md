# Plan de travail SymQ — organisation, performance, stabilité, usabilité

Document destiné à l'agent d'exécution. Base : `yoch/symq` `main@d18e018` (= `claude/kind-euler-uigoky`).
Livraison : ce plan sera commité en `docs/plans/2026-10-31-workplan.md` sur la branche
`claude/kind-euler-uigoky`, poussé, et une PR brouillon ouverte. L'exécution des lots se fait
ensuite en PR séparées et révisables (règle AGENTS.md : aucun merge sans autorisation séparée).

## Contexte

SymQ est un toolkit Python de vérification exacte de circuits réversibles (ANF sur F2, ZDD Python
et cœur C CPython de 2 754 lignes, moteur SAT, programmes HMR à phases ±1, canaux quantiques
restreints). Il a été produit en 4 jours (230 commits, 27–30 oct. 2026) par plusieurs agents, ce
qui a laissé :

- **Organisation** : 442 fichiers, dont 0,7 Mo de code source contre 6,8 Mo de `research/` +
  `benchmarks/` ; 33 des 80 fichiers de tests dépendent de `research/`, `benchmarks/` ou de
  commits distants ; 3 workflows CI rejouent des audits ponctuels ; 3 feuilles de route et 6
  documents d'audit redondants ; docs publiques en anglais, recherche en français.
- **Performance** : aucune sortie anticipée dans `check_equivalence`, `max_terms` non appliqué
  dans la boucle C, cache Python ZDD vidé en bloc, encodeur SAT non optimisé, aucun suivi de
  performance en CI, 6 harnais de benchmark aux formats différents.
- **Stabilité** : capacités `uint32` doublées sans garde dans le C, 5 mécanismes d'horloge
  distincts, réservation de session perdue dans `collect_roots`, témoins de phase jamais rejoués,
  build natif non portable (gcc-only, macOS/Windows jamais testés), suite de tests par défaut qui
  touche le réseau et mute `.git`.
- **Usabilité** : deux façades de vérification incompatibles, 6 formes de résultats, 3 hachages
  de programme, collisions de noms (`PhaseProgram`, `check_equivalence`, `composition`, `qcec`,
  `BACKENDS`, `Contract`), CLI incapable de comparer deux circuits classiques ou QASM, `doctor`
  qui renvoie 1 sans natif, pas de `py.typed`, pas de CHANGELOG, pas de référence API.

Un utilisateur aval de symq (projet de compilation de circuits vérifiables) a documenté les
limites rencontrées en pratique : largeur native 64 (cas bloqués à 72, 93, 126 et 128 fils
couplés), SAT inconcluant sur un multiplicateur GF(2¹²) à 36 fils, préconditions de domaine non
exprimables comme constantes, vérificateurs HMR réécrits plusieurs fois à la main, parseurs
`.kmx` (format kickmix de Qualtran) ad hoc. Ces constats guident le lot d'enrichissement.
Contrainte : aucune fixture ni donnée privée n'entre dans symq ; seules des constructions
mathématiques publiques et le corpus kickmix public (Qualtran, Apache-2.0) sont utilisés.

Décisions prises avec l'utilisateur : archivage sur **branche `research-archive` + tag** dans
symq ; `experimental` **aminci + sous-paquet `symq.labs`** ; plan livré **dans le dépôt + PR
brouillon**.

## Principes d'exécution

1. Une PR par lot ou sous-lot, petite, avec tests différentiels contre un oracle simple et
   mutants pour toute optimisation symbolique (AGENTS.md).
2. Aucun changement de théorème accepté sans l'écrire ; fail-closed partout.
3. Les fichiers scellés (`MANIFEST.sha256`, `SHA256SUMS`) ne sont jamais réécrits : ils sont
   déplacés d'un seul bloc vers la branche d'archive, hash préservés, avec un index de
   correspondance (`docs/archive-index.md`).
4. Toute mesure de performance : SHA source + binaire, machine, répétitions, distributions
   appariées, coûts de conversion (jamais un seul circuit pathologique).
5. Langue des documents publics : anglais. Ce plan reste en français.

1. **Importeur kickmix** `symq.kickmix.parse_kmx` : X/CX/CCX/SWAP/CSWAP/CZ/CCZ/Z/NEG/HMR,
   `BIT_*`, variantes `_IF` ; rejet strict de `R`/`Z_POW`. Lowering vers `Circuit` (partie
   réversible) et vers le programme HMR unifié. Corpus de test : `qualtran/kickmix/testdata/*.kmx`
   au commit `638777f` (Apache-2.0 ; `inc3`, `inc8`, `cmul16_mod_21`, `iadd8_qc_2clean_6dirty`,
   `mul16_mod_21`, `big_circuit`), copiés avec licence et provenance dans `benchmarks/corpus/kickmix/`.
2. **Largeur native > 64 fils couplés** (issue #57) : la limite la plus citée (72, 93, 126, 128,
   195 fils). Mode wide déjà à 128 pour import/export ; étendre masques/témoins à 256 par
   stockage d'indices par niveau, benchmark sur circuits **connectés** (GF(2²⁴) 72 fils,
   loaders 126 fils générés publiquement) vs `zdd` Python et découpage par blocs.
3. **Chemin rapide linéaire/affine** : segments X/CX/SWAP → égalité de matrices GF(2) + offset
   affine, en O(gates·width/64) ; cible : étages linéaires de centaines de milliers de portes sur ~800 fils.
4. **Préconditions de contrat au-delà des constantes** dans `sat.Contract` et le vérificateur
   ANF : relations affines (`bit7 == bit6`), domaines finis explicites (intervalle
   d'entiers `[lo, hi]`), avec témoin rejoué dans le domaine.
5. **Vérificateur HMR symbolique unifié** (`symq.phase` v2) : symbole frais par HMR, CZ/Z/NEG
   conditionnés, polynôme de phase séparé, **bits classiques d'entrée comme variables** (masques
   dynamiques), budget ; remplace les réimplémentations ad hoc côté utilisateur et absorbe
   `hmr_feedback`. Oracle : interpréteur scalaire existant + `phase_oracle`.
6. **Générateurs publics** `symq.generators` : multiplicateurs GF(2ⁿ) (schoolbook n² CCX,
   Karatsuba, décomposition à 42 ANDs pour n=12), GF(2²⁴) mod `0x100001b`, Frobenius/carré,
   normes `a² + ab + K·b²`, division monique, addition signée modulaire, additionneurs
   Cuccaro/Gidney, comparateurs, QROM/SelectSwap avec cibles sales. Servent de corpus de
   benchmark « arithmétique dure » (issue #46) et de tests de mutation.
7. **`symq.check_rewrite(before, after, contract)`** pour valider chaque instance d'une passe de
   réécriture (fusion de Toffoli, déplacements commutants, CCX→CX restreint au domaine) ; API
   incrémentale réutilisant un manager et les racines de référence pour les boucles de recherche
   (beam search), là où collecte et ordre comptent vraiment.
8. **Comptage de ressources** : Toffoli-like (CCX/CCZ/CSWAP et `_IF`), CX/CZ conditionnés
   gratuits, nombre de HMR, pic de qubits vivants ; rapporté dans `VerificationResult`.
9. **`symq doctor --json`** : commit, ABI, SHA du binaire natif, SHA des sources ; remplace le
   qualificateur de 193 lignes réécrit côté consommateur ; sortie DRAT optionnelle du solveur
   pour les `equivalent` SAT.

Acceptation : chaque fonctionnalité a un oracle indépendant (énumération ≤ 20 bits, scalaire),
des mutants, et un cas du corpus kickmix ou des générateurs ; les limites restent écrites
(« ne prouve pas la fermeture des phases Z_POW »).

## Risques et garde-fous

- **Hash scellés** : ne jamais réécrire ; déplacer en bloc, index de correspondance,
  `verify_archive.py` exécuté sur la branche d'archive en CI mensuelle.
- **Dérive sémantique** pendant l'unification : tests différentiels entre ancienne et nouvelle
  façade sur tout le corpus avant suppression des alias.
- **Performance mal mesurée** : harnais continu livré avant toute optimisation ; holdout jamais
  utilisé pour régler.
- **Portée quantique** : les nouveaux vérificateurs HMR restent « branche ±1 sous O1/O2 » ou
  « canal restreint » ; aucune promesse de vérification quantique générale.
- **Confidentialité** : rien de privé n'est copié ; revue des README pour supprimer les chemins
  privés.
